# DRAFT-T2 — 画面修复报告

## 已解决：`SUBJECT_LAYER 画 0`（以及它真正的含义）

### 根因是一个**不存在的导出名**

```js
// 错：PLAN 没有 SHOT_FRAMES 导出（它是 undefined），guard 每帧立即返回
const S6 = PLAN.SHOT_FRAMES && PLAN.SHOT_FRAMES['S6-name-fracture'];

// 对：SHOTS 是数组
const S6 = PLAN.SHOTS.find((x) => x.id === 'S6-name-fracture');
```

`draftt-plan.mjs` 实际导出：`FPS, PLANNED, PLANNED_WITH_LAYERS, SHOTS, TOTAL_FRAMES`。
**`SHOT_FRAMES` 从来不存在**，所以 `S6` 是 `undefined`，函数在第一个 guard 就 `return 0`。

**后果**：碎裂材质**从未被绘制**，而渲染**始终报成功**，唯一症状是「画面没变」。
`: `typeof` 探针打在 guard 上才定位到它——层账本显示 `画 0`、而函数**确实被调用**（`CALLED f=311`），
所以故障必然在函数内部。

### 第二个缺陷：层未声明

`SUBJECT_LAYER` 原先**没有在镜头计划里声明**。引擎按 `intent.layers` 迭代合成，
所以写进 `cvSubject` 的像素被静默丢弃，账本里连该层都不出现。

**引擎这样做是正确的**（层必须声明），但**症状（画面没变）与原因（层未声明）之间没有任何提示**。

### 最终做法

碎裂材质画进 **`SCENE_LAYER`** —— 这部片子的镜头确实声明了它，且它已被证明能到达画面。
不假装主体槽有内容：该槽仍在层契约中声明与绘制，但没有为它编造任何东西。

## 两个缺陷的性质不同，值得区分

| | 缺陷 | 为什么没被更早发现 |
|---|---|---|
| 1 | 场景墙用 `line()` 描线而非填充面 | 不是错误，是**设计不足**；只有量了像素墨覆盖才看出来 |
| 2 | `PLAN.SHOT_FRAMES` 不存在 | **典型笔误**，但 `undefined && ...` 不抛错，只静默返回 |
| 3 | `SUBJECT_LAYER` 未在计划声明 | 引擎**正确地**丢弃了未声明层的像素——**契约生效，但无反馈** |

缺陷 2 与 3 合起来制造了一个**完全静默的失败**：代码在跑、渲染在成功、画面不变。
这解释了为什么我在此消耗了多轮——**每一次「合理的尝试」都没有任何信号返回**。

**可复用的教训**：当「画面不变」时，先用 `typeof` / 存在性探针确认**你读的东西存在**，
再怀疑参数调优。`undefined` 参与 `&&` 运算不会报错。
